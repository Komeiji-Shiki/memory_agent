# 🔧 分规划三：迭代检索器（MemR3 风格）

## 📋 概述

本分规划对应总规划的 **Phase 3**，实现 MemR3 风格的迭代检索机制。

**核心思想**：传统的 Retrieve-then-Answer 模式可能因为一次检索不完整而导致回答不准确。MemR3 通过「Retrieve → Reflect → Refine」闭环，确保收集足够的证据后再回答。

**示例**：
```
传统模式:
    用户: "主人领养 Buddy 多久了？"
    检索: 找到 "2024年12月领养了Buddy"
    回答: "主人在2024年12月领养了Buddy" ← 没回答"多久"！

迭代检索:
    用户: "主人领养 Buddy 多久了？"
    检索1: 找到 "2024年12月领养了Buddy"
    反思: 知道领养日期，但缺少"现在时间"来计算时长
    检索2: 查询当前日期相关信息
    回答: "主人领养Buddy已经2个月了" ✓
```

**预计工期**：3-4 天（已完成核心模块）

## 📐 复杂度分类规则

### QueryComplexity 判断逻辑

| 复杂度 | 触发条件 | 检索策略 |
|--------|---------|---------|
| **SIMPLE** | 查询≤15字符 / 是非问题 / 精确查找 | 单次检索 |
| **MEDIUM** | 普通问题 / 单个复杂模式 | 迭代检索（限制2轮） |
| **COMPLEX** | 多个复杂模式 / 查询≥50字符 | 完整迭代检索（3轮） |

### 复杂模式检测

```python
# 触发 COMPLEX 的模式
complex_patterns = [
    r"(为什么|怎么|如何)",           # 因果/方法
    r"(比较|对比|区别|不同|相同)",    # 比较
    r"(变化|发展|演化|历史|过程)",    # 时序演化
    r"(关系|联系|相关|影响)",         # 深层关系
    r"(总结|分析|评价|评估)",         # 综合分析
    r"(多久|多长时间|持续)",          # 时间计算
]

# 触发 SIMPLE 的模式
simple_patterns = [
    r"^.{0,15}是(谁|什么)$",          # "xxx是谁/什么"
    r"^(有没有|是否|能不能)",          # 是非问题
    r"^(查|搜|找).{0,10}$",            # 短查询
]
```

## ⚙️ 配置说明

### config.jsonc 新增配置

```jsonc
{
    "graphiti": {
        // ... 其他配置 ...
        
        // 检索策略配置（MemR3 风格迭代检索）
        "retrieval": {
            "strategy": "auto",        // auto | single | iterative
            "max_iterations": 3,       // 最大迭代次数
            "min_evidence_count": 2,   // 最少证据数量
            "default_limit": 10,       // 每次检索结果数
            
            // 复杂度分类阈值
            "complexity": {
                "simple_max_length": 15,   // 简单查询最大长度
                "complex_min_length": 50   // 复杂查询最小长度
            },
            
            // LLM 反思（成本较高，可选）
            "enable_llm_reflect": false
        }
    }
}
```

### 策略说明

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| `auto` | 根据复杂度自动选择 | **推荐**，平衡效果和成本 |
| `single` | 强制单次检索 | 成本敏感场景 |
| `iterative` | 强制迭代检索 | 需要高准确率的场景 |

## 🧪 使用示例

### 基本使用

```python
from memory_agent.retrieval_router import create_retrieval_router

# 创建路由器
router = create_retrieval_router(
    graphiti_adapter=graphiti,
    config={
        "max_iterations": 3,
        "min_evidence_count": 2,
        "enable_llm_reflect": False
    }
)

# 执行检索
result = router.retrieve("主人领养 Buddy 多久了？")

print(f"策略: {result.strategy}")
print(f"迭代次数: {result.iterations}")
print(f"证据数量: {len(result.evidence)}")
print(f"摘要:\n{result.evidence_summary}")
```

### 强制使用特定策略

```python
# 强制单次检索（节省成本）
result = router.retrieve(
    query="灰魂是谁？",
    force_strategy="single"
)

# 强制迭代检索（高准确率）
result = router.retrieve(
    query="主人最近三个月的学习进展如何？",
    force_strategy="iterative"
)
```

### 异步使用

```python
import asyncio

async def search():
    result = await router.retrieve_async(
        query="比较 LifeBook 和传统笔记的区别",
        context="用户在讨论记忆管理工具"
    )
    return result

result = asyncio.run(search())
```

## ⚠️ 注意事项

### 成本控制

迭代检索可能消耗更多资源：
- 每次迭代调用一次 Graphiti.search
- 如果启用 LLM 反思，每次迭代还调用 LLM

**建议**：
- 默认关闭 `enable_llm_reflect`
- 使用 `strategy: auto` 让系统自动判断
- 监控迭代次数，超过预期时检查复杂度分类

### 与现有系统的关系

```
当前检索流程:
    MemoryAgent → MemoryTools → graphiti_search → GraphitiAdapter

新增迭代检索:
    RetrievalRouter → IterativeRetriever → GraphitiAdapter
                  ↓
            (可选) 替换 MemoryAgent 中的检索逻辑
```

迭代检索器是**可选增强**，不强制替换现有流程。
