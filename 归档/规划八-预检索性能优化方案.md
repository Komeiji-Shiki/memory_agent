# ⚡ 预检索性能优化方案

## 📊 当前瓶颈分析

### deepseek-reasoner 的耗时

```
用户请求 → Agent 预检索 → 主模型回复
              │
              ▼
         deepseek-reasoner
         ├── 思维链生成：2-5s
         ├── 工具调用：0.5-1s
         ├── 结果整合：1-2s
         └── 总计：3-10s（每次迭代）
         
         如果迭代2-3次：6-30s ← 这是主要瓶颈
```

### 为什么当前用 deepseek-reasoner？

| 优势 | 说明 |
|------|------|
| 智能判断 | 自动判断是否需要检索 |
| 工具调用 | 自主选择合适的工具和参数 |
| 关键词调整 | 搜不到会换词再搜 |
| 信息整合 | 把多次搜索结果组织好 |

**核心问题**：这些能力是否必须用 LLM 实现？

---

## 🎯 三种替代方案

### 方案 A：快速模型替代

用更快的模型替代 deepseek-reasoner：

| 模型 | 首字延迟 | 工具调用能力 | 成本 |
|------|---------|-------------|------|
| deepseek-reasoner | 2-5s | ⭐⭐⭐⭐⭐ | 低 |
| **gemini-2.0-flash** | 0.3-0.5s | ⭐⭐⭐⭐ | 低 |
| **gpt-4o-mini** | 0.3-0.5s | ⭐⭐⭐⭐ | 低 |
| claude-3-haiku | 0.5-1s | ⭐⭐⭐⭐ | 低 |
| Qwen-72B | 0.5-1s | ⭐⭐⭐ | 低 |

**改动量**：仅修改配置

```jsonc
// config.jsonc
{
    "memory_agent": {
        "model": "gemini-2.0-flash",  // 改这里
        "base_url": "https://generativelanguage.googleapis.com/v1beta/openai/",
        "api_key": "..."
    }
}
```

**预期效果**：
- 单次检索：3-10s → **0.5-2s**
- 总耗时：6-30s → **1-5s**

**风险**：
- 工具调用准确性可能下降
- 关键词调整能力可能变弱
- 需要测试验证

### 方案 B：无 LLM 规则检索

完全不用模型做预检索，用规则 + 本地搜索：

```
用户请求
    │
    ▼
┌─────────────────────────────────────────────────────┐
│               Query Analyzer (规则引擎)              │
│                                                     │
│  1. 关键词提取（jieba 分词）                        │
│  2. 时间表达式识别（"去年"→2025）                   │
│  3. 人物识别（识别人名）                            │
│  4. 意图分类（问事实/问关系/闲聊）                  │
└─────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────┐
│               Hybrid Search (混合搜索)               │
│                                                     │
│  1. 关键词搜索（SQLite 倒排索引）                   │
│  2. 语义搜索（RAG 向量）                            │
│  3. 图搜索（Graphiti）← 如果已集成                  │
│  4. 结果融合 + 去重                                 │
└─────────────────────────────────────────────────────┘
    │
    ▼
直接注入到主模型上下文（无需 Agent 整合）
```

**实现示例**：

```python
# memory_agent/fast_retriever.py

import jieba
import re
from datetime import datetime, timedelta

class FastRetriever:
    """无 LLM 的快速检索器"""
    
    def __init__(self, memory_tools, rag_searcher=None, graphiti=None):
        self.tools = memory_tools
        self.rag = rag_searcher
        self.graphiti = graphiti
    
    def retrieve(self, query: str, context: str = "") -> str:
        """快速检索"""
        start = time.time()
        
        # 1. 判断是否需要检索（简单规则）
        if self._is_casual_chat(query):
            return ""  # 闲聊不检索
        
        # 2. 提取关键信息
        keywords = self._extract_keywords(query)
        time_range = self._extract_time_range(query)
        people = self._extract_people(query)
        
        # 3. 并行搜索
        results = []
        
        # 关键词搜索
        if keywords:
            kw_results = self.tools.call_tool("search_memories", {
                "query": " ".join(keywords),
                "date_start": time_range.get("start"),
                "date_end": time_range.get("end"),
                "limit": 5
            })
            results.append(("keywords", kw_results))
        
        # 语义搜索
        if self.rag:
            rag_results = self.tools.call_tool("rag_search", {
                "query": query,
                "top_k": 3
            })
            results.append(("semantic", rag_results))
        
        # 人物节点
        for person in people:
            node_result = self.tools.call_tool("get_node", {"name": person})
            if "未找到" not in node_result:
                results.append(("person", node_result))
        
        # 4. 融合结果
        elapsed = time.time() - start
        return self._merge_results(results, elapsed)
    
    def _is_casual_chat(self, query: str) -> bool:
        """判断是否闲聊"""
        casual_patterns = [
            r"^(你好|嗨|hi|hello)",
            r"^(今天.*怎么样|天气)",
            r"^(帮我|请|能不能).*写.*",  # 写作请求
            r"^(解释|什么是|介绍).*",     # 知识问答
        ]
        for pattern in casual_patterns:
            if re.match(pattern, query, re.IGNORECASE):
                return True
        return False
    
    def _extract_keywords(self, query: str) -> list:
        """提取关键词"""
        # 去掉常见停用词
        stopwords = {"的", "是", "在", "我", "有", "和", "了", "不", "人", "都", "你", "什么", "吗", "吧"}
        words = jieba.cut(query)
        return [w for w in words if len(w) > 1 and w not in stopwords]
    
    def _extract_time_range(self, query: str) -> dict:
        """提取时间范围"""
        now = datetime.now()
        
        patterns = {
            r"去年": (now.replace(year=now.year-1, month=1, day=1), 
                     now.replace(year=now.year-1, month=12, day=31)),
            r"上个月": (now.replace(day=1) - timedelta(days=1)).replace(day=1),
            r"最近(\d+)天": lambda m: (now - timedelta(days=int(m.group(1))), now),
            r"(\d{4})年(\d{1,2})月": lambda m: (
                datetime(int(m.group(1)), int(m.group(2)), 1),
                datetime(int(m.group(1)), int(m.group(2)) + 1, 1) - timedelta(days=1)
            ),
        }
        
        for pattern, handler in patterns.items():
            match = re.search(pattern, query)
            if match:
                if callable(handler):
                    start, end = handler(match)
                else:
                    start, end = handler
                return {
                    "start": start.strftime("%Y-%m-%d"),
                    "end": end.strftime("%Y-%m-%d")
                }
        
        return {}
    
    def _extract_people(self, query: str) -> list:
        """提取人物名称"""
        # 简单实现：检查是否包含已知人物
        # 实际可以用 NER 模型
        known_people = ["灰魂", "主人", "小明", ...]  # 从节点列表获取
        return [p for p in known_people if p in query]
    
    def _merge_results(self, results: list, elapsed: float) -> str:
        """融合搜索结果"""
        if not any(r[1] and "未找到" not in r[1] for r in results):
            return ""
        
        output = f"## 📚 相关记忆（{elapsed:.2f}s）\n\n"
        for source, content in results:
            if content and "未找到" not in content:
                output += f"### {source}\n{content[:500]}\n\n"
        
        return output
```

**预期效果**：
- 检索耗时：3-30s → **50-200ms** 🚀
- 适用场景：90% 的简单查询

**局限性**：
- 复杂问题处理能力下降
- 无法调整关键词
- 无法理解隐含意图

### 方案 C：混合方案（推荐）

结合规则检索和快速模型，**分层处理**：

```
用户请求
    │
    ▼
┌─────────────────────────────────────────────────────┐
│          Query Classifier (轻量分类器)              │
│                                                     │
│  判断查询复杂度：                                   │
│  - 简单：直接本地搜索                               │
│  - 中等：快速模型（gemini-flash）                   │
│  - 复杂：deepseek-reasoner                         │
└─────────────────────────────────────────────────────┘
    │
    ├──────────────────┬──────────────────┐
    ▼                  ▼                  ▼
┌─────────┐      ┌─────────┐       ┌─────────┐
│  简单   │      │  中等   │       │  复杂   │
│ 50-100ms│      │ 0.5-2s  │       │ 3-10s   │
└─────────┘      └─────────┘       └─────────┘
  规则检索        快速模型          推理模型
```

**分类规则**：

| 类型 | 特征 | 示例 | 处理方式 |
|------|------|------|----------|
| **简单** | 明确的关键词/人物/日期 | "灰魂是谁"、"1月20号做了什么" | 规则检索 |
| **中等** | 需要一定理解但不复杂 | "最近在做什么项目" | gemini-flash |
| **复杂** | 多步推理/时序比较/因果分析 | "去年项目遇到的问题和解决方案" | deepseek |

**实现**：

```python
# memory_agent/hybrid_agent.py

class HybridAgent:
    """混合检索 Agent"""
    
    def __init__(self, config):
        # 规则检索器
        self.fast = FastRetriever(...)
        
        # 快速模型（用于中等复杂度）
        self.medium_client = OpenAI(
            api_key=config["gemini_key"],
            base_url="https://generativelanguage.googleapis.com/v1beta/openai/"
        )
        
        # 推理模型（用于复杂问题）
        self.complex_client = OpenAI(
            api_key=config["deepseek_key"],
            base_url="https://api.deepseek.com/v1"
        )
    
    def retrieve(self, query: str, context: str = "") -> str:
        complexity = self._classify_complexity(query)
        
        if complexity == "simple":
            return self.fast.retrieve(query, context)
        
        elif complexity == "medium":
            return self._medium_retrieve(query, context)
        
        else:  # complex
            return self._complex_retrieve(query, context)
    
    def _classify_complexity(self, query: str) -> str:
        """分类查询复杂度"""
        # 复杂指标
        complex_indicators = [
            r"(和|以及|还有).*什么",  # 多部分问题
            r"(为什么|怎么|如何)",     # 因果/方法问题
            r"(变化|发展|演化)",       # 时序问题
            r"(比较|对比|区别)",       # 比较问题
            r"(关系|联系|相关)",       # 关系问题
        ]
        
        # 简单指标
        simple_indicators = [
            r"^.{0,10}是谁",           # "xxx是谁"
            r"^\d{4}.*做了什么",       # 日期查询
            r"^(有没有|是否)",         # 是非问题
        ]
        
        for pattern in complex_indicators:
            if re.search(pattern, query):
                return "complex"
        
        for pattern in simple_indicators:
            if re.search(pattern, query):
                return "simple"
        
        return "medium"  # 默认中等
```

**预期效果**：
- 简单查询：50-200ms
- 中等查询：0.5-2s
- 复杂查询：3-10s
- **平均**：大幅下降（因为大部分查询是简单/中等）

### 方案 D：Graphiti 原生检索（配合图存储改造）

如果已经整合了 Graphiti，它自带高效的混合检索：

```python
# Graphiti 内置搜索
results = await graphiti.search(
    query,
    num_results=10
)
# 自动做：语义搜索 + BM25 + 图遍历
# 响应时间：亚秒级
```

**流程变化**：

```
当前：用户请求 → Agent(LLM) → 工具调用 → 搜索 → LLM整合 → 输出
      └──────────────── 3-30s ────────────────┘

Graphiti：用户请求 → Graphiti.search() → 直接输出
          └────── 100-500ms ──────┘
```

**但是**：仍然需要判断"是否需要检索"，可以用简单规则或快速模型

## ⚠️ 注意事项

### 不要完全去掉智能检索

即使用快速方案，也要保留"是否需要检索"的判断：

```python
# 错误做法：每次都搜索
def retrieve(query):
    return search(query)  # 闲聊也搜，浪费

# 正确做法：先判断
def retrieve(query):
    if is_casual_chat(query):
        return ""  # 闲聊不搜
    return search(query)
```

### 保留回退选项

复杂问题仍然需要 deepseek-reasoner：

```python
if complexity == "complex":
    # 仍用 deepseek，宁可慢也要准
    return deepseek_agent.retrieve(query)
```
