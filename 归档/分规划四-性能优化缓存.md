## 🏗️ 架构设计

### 缓存层次

```
┌─────────────────────────────────────────────────────────────────┐
│                      RetrievalRouter                             │
│  (入口：自动管理缓存)                                             │
└─────────────────────────────┬───────────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
┌─────────────────────────────┐    ┌─────────────────────────────┐
│     RetrievalCache          │    │    IterativeRetriever       │
│  (查询规范化 + 缓存)         │    │  (复杂查询，不缓存整体)      │
└─────────────┬───────────────┘    └─────────────────────────────┘
              │
              ▼
┌─────────────────────────────┐
│      LRUTTLCache            │
│  (LRU + TTL 双重淘汰)        │
│  - OrderedDict O(1) 操作    │
│  - 线程安全（RLock）         │
│  - 统计信息收集              │
└─────────────────────────────┘
```

### 缓存键规范化流程

```
原始查询: "主人 最近 在学什么？？"
    ↓
去除首尾空白
    ↓
统一小写: "主人 最近 在学什么？？"
    ↓
去除标点: "主人 最近 在学什么"
    ↓
压缩空白: "主人 最近 在学什么"
    ↓
MD5 哈希: "a1b2c3d4e5f6..."
    ↓
缓存键
```

## 🧪 使用示例

### 基本使用

```python
from memory_agent.retrieval_router import create_retrieval_router

# 创建路由器（自动启用缓存）
router = create_retrieval_router(
    graphiti_adapter=graphiti,
    config={
        "cache": {
            "enabled": True,
            "ttl_seconds": 300,
            "max_size": 1000,
        }
    }
)

# 第一次检索（缓存未命中）
result1 = router.retrieve("灰魂是谁？")
print(result1.cached)  # False

# 第二次相同查询（缓存命中）
result2 = router.retrieve("灰魂是谁？")
print(result2.cached)  # True
print(result2.strategy)  # "cached"
```

### 缓存预热

```python
# 预热常用查询
warmup_stats = router.warmup_cache(num_results=5)
print(warmup_stats)  # {"主人": 10, "灰魂": 8, ...}

# 添加自定义预热查询
router.add_warmup_query("最近的项目")
router.warmup_cache()
```

### 缓存管理

```python
# 查看统计
stats = router.get_cache_stats()
print(f"命中率: {stats['hit_rate']}")
print(f"缓存大小: {router.cache_size}")

# 清空特定查询
router.invalidate_cache("灰魂是谁")

# 清空全部
router.clear_cache()
```

### 使用装饰器

```python
from memory_store.retrieval_cache import cached, create_retrieval_cache

cache = create_retrieval_cache({"cache": {"ttl_seconds": 600}})

@cached(cache, key_fn=lambda q, **kw: q)
def my_search(query: str, num_results: int = 10):
    return graphiti.search(query, num_results=num_results)

# 自动缓存结果
results = my_search("主人的项目")
```

| 热门查询（预热后） | ~200ms | ~1ms | **200x** |

### 内存占用估算

```
假设：
- 每条证据平均 500 字节
- 每次检索返回 10 条
- 最大缓存 1000 条查询

单条查询缓存: 10 × 500B = 5KB
最大内存占用: 1000 × 5KB = 5MB

结论：内存占用完全可接受
```

## 📐 设计特点

### 1. LRU + TTL 双重淘汰

```python
class LRUTTLCache:
    """
    淘汰策略：
    1. TTL 过期 → 立即无效
    2. 容量超限 → 淘汰最久未访问的
    """
```

### 2. 查询规范化

相似的查询会映射到同一个缓存键：
- "灰魂是谁？" → "灰魂是谁"
- "灰魂 是 谁" → "灰魂是谁"
- "灰魂是谁" → "灰魂是谁"

### 3. 泛型支持

```python
class LRUTTLCache(Cache[str, T]):
    """支持任意类型的值"""
```

### 4. 线程安全

使用 `threading.RLock` 保证并发安全。

### 5. 统计信息

```python
stats = cache.stats
# {
#     "hits": 150,
#     "misses": 50,
#     "hit_rate": "75.00%",
#     "evictions": 10,
#     "size": 200,
#     "max_size": 1000
# }
```

## ⚠️ 注意事项

### 缓存一致性

- 当知识图谱更新后，相关缓存可能过期
- 建议在数据更新后调用 `clear_cache()` 或设置较短的 TTL
- 迭代检索的**最终结果不缓存**（因为中间过程可能不同）

### 复杂查询

- 迭代检索（MEDIUM/COMPLEX）的**单步检索**会命中缓存
- 但整体迭代结果不缓存，因为上下文可能影响结果

### 成本权衡

| 配置 | 内存占用 | 命中率 | 适用场景 |
|------|---------|--------|---------|
| TTL=60s, max=100 | 极低 | 低 | 测试环境 |
| TTL=300s, max=1000 | 中等 | 高 | **生产环境推荐** |
| TTL=3600s, max=5000 | 较高 | 很高 | 查询模式稳定 |
