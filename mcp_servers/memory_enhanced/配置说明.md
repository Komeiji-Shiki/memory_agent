# Memory Enhanced v2.0 配置说明

## 📋 配置文件位置

配置文件：[`config.json`](config.json)

所有配置通过环境变量设置，在 `config.json` 的 `env` 字段中定义。

## ⚙️ 可用配置项

### 1. GEMINI_API_KEY（必需）
- **类型**: 字符串
- **默认值**: 无
- **说明**: Google Gemini API密钥
- **示例**: `"AIzaSy..."`

### 2. MEMORY_FILE_PATH（必需）
- **类型**: 字符串
- **默认值**: `"memory.jsonl"`
- **说明**: 记忆文件路径（相对路径）
- **示例**: `"mcp_servers/memory2/memory.jsonl"`

### 3. MEMORY_BATCH_SIZE（可选）
- **类型**: 整数
- **默认值**: `50`
- **说明**: 批量处理的批次大小
- **范围**: 1-1000
- **作用**: 控制进度显示和错误恢复的粒度
- **示例**: `"100"`

**注意**: 这个"批次"是指进度报告的粒度，**不会减少API调用次数**。Gemini API 不支持真正的批量embedding，每个实体仍需要单独调用一次API。批次的作用是：
- ✅ 显示进度（例如：批次 1/20 完成）
- ✅ 错误恢复（某批次失败时只重试该批次）
- ❌ 不减少API调用次数

### 4. MEMORY_SIMILARITY_THRESHOLD（可选）
- **类型**: 浮点数
- **默认值**: `0.3`
- **说明**: 语义搜索的相似度阈值
- **范围**: 0.0-1.0
- **作用**: 低于此阈值的结果会被过滤
- **示例**: `"0.4"`

**调整建议**:
- `0.2`: 更宽松，返回更多结果（可能不太相关）
- `0.3`: 平衡（推荐）
- `0.4-0.5`: 更严格，只返回高度相关的结果

### 5. MEMORY_CACHE_ENABLED（可选）
- **类型**: 布尔值
- **默认值**: `true`
- **说明**: 是否启用向量缓存
- **示例**: `"true"` 或 `"false"`

**禁用缓存的场景**:
- 测试调试
- 记忆文件频繁变化
- 存储空间受限

**启用缓存的优势**:
- ✅ 启动速度快（0.6秒 vs 25秒）
- ✅ 支持增量更新
- ✅ 节省API配额

### 6. MEMORY_USE_BINARY_CACHE（可选）
- **类型**: 布尔值
- **默认值**: `true`
- **说明**: 使用二进制(Pickle)格式缓存，而不是JSON
- **示例**: `"true"` 或 `"false"`

**格式对比**:

| 特性 | Pickle (二进制) | JSON (文本) |
|------|----------------|-------------|
| 文件大小 | 5MB | 15MB |
| 加载速度 | 0.6秒 | 2.5秒 |
| 人类可读 | ❌ | ✅ |
| 推荐使用 | ✅ | ❌ |

## 📝 完整配置示例

```json
{
    "name": "memory_enhanced",
    "description": "增强型记忆服务 v2.0",
    "version": "2.0.0",
    "type": "stdio",
    "command": "python",
    "args": ["mcp_servers/memory_enhanced/server.py"],
    "env": {
        "PYTHONIOENCODING": "utf-8",
        
        // 必需配置
        "GEMINI_API_KEY": "your-api-key-here",
        "MEMORY_FILE_PATH": "mcp_servers/memory2/memory.jsonl",
        
        // 可选配置（使用默认值可以不设置）
        "MEMORY_BATCH_SIZE": "50",
        "MEMORY_SIMILARITY_THRESHOLD": "0.3",
        "MEMORY_CACHE_ENABLED": "true",
        "MEMORY_USE_BINARY_CACHE": "true"
    }
}
```

## 🔧 配置场景示例

### 场景1：默认配置（推荐）
适合大多数用户：
```json
"env": {
    "GEMINI_API_KEY": "your-key",
    "MEMORY_FILE_PATH": "memory.jsonl"
}
```

### 场景2：大量实体（1000+）
提高批次大小以减少进度输出：
```json
"env": {
    "GEMINI_API_KEY": "your-key",
    "MEMORY_FILE_PATH": "memory.jsonl",
    "MEMORY_BATCH_SIZE": "100"
}
```

### 场景3：更严格的搜索
提高相似度阈值，只返回高度相关结果：
```json
"env": {
    "GEMINI_API_KEY": "your-key",
    "MEMORY_FILE_PATH": "memory.jsonl",
    "MEMORY_SIMILARITY_THRESHOLD": "0.5"
}
```

### 场景4：调试模式
禁用缓存，每次都重新生成向量：
```json
"env": {
    "GEMINI_API_KEY": "your-key",
    "MEMORY_FILE_PATH": "memory.jsonl",
    "MEMORY_CACHE_ENABLED": "false"
}
```

### 场景5：存储空间优先
使用JSON缓存（文件更大但可读）：
```json
"env": {
    "GEMINI_API_KEY": "your-key",
    "MEMORY_FILE_PATH": "memory.jsonl",
    "MEMORY_USE_BINARY_CACHE": "false"
}
```

## ⚠️ 重要说明

### 关于"批量处理"
**批量处理并不减少API调用次数！**

- ❌ **不是**: 一次API调用处理50个实体
- ✅ **而是**: 50个实体为一组，显示一次进度

**为什么这样设计？**
1. Gemini API 的 `embed_content` 不支持批量处理多个文档
2. 批次主要用于：
   - 进度显示（避免输出过多）
   - 错误恢复（批次失败时只重试该批次）
   - 代码组织（便于扩展）

**真正的性能提升来自**:
- ✅ **二进制缓存**: 减少60%文件大小，提升3-5倍加载速度
- ✅ **增量更新**: 只为新增实体生成向量
- ✅ **智能缓存**: 启动时检查缓存有效性

### API调用次数

```
实体数量 = API调用次数
```

例如：
- 28个实体 = 28次API调用（首次）
- 28个实体 = 0次API调用（使用缓存）
- 新增5个实体 = 5次API调用（增量更新）

### 如何节省API配额

1. **启用缓存**（默认已启用）
   ```json
   "MEMORY_CACHE_ENABLED": "true"
   ```

2. **使用增量更新**（自动）
   - 缓存存在时，只为新增实体生成向量

3. **定期清理**
   - 删除不需要的旧实体

4. **使用关键词搜索**
   - 不需要API调用
   ```json
   {"search_mode": "keyword"}
   ```

## 🆘 常见问题

### Q1: 修改配置后不生效？
**A**: 需要重启服务器才能应用新配置。

### Q2: 批次大小设置多少合适？
**A**: 
- 小型（<100实体）: 50（默认）
- 中型（100-500）: 100
- 大型（>500）: 200

### Q3: 如何完全禁用缓存？
**A**: 
```json
"MEMORY_CACHE_ENABLED": "false"
```

### Q4: 缓存文件在哪里？
**A**: 
- 二进制格式: `memory.jsonl.embeddings.pkl`
- JSON格式: `memory.jsonl.embeddings.json`

### Q5: 可以手动删除缓存吗？
**A**: 可以。删除后下次启动会自动重新生成。

## 🔄 配置更新流程

1. 编辑 `config.json`
2. 保存文件
3. 重启MCP服务器
4. 查看启动日志确认配置生效
