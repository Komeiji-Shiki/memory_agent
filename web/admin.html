📝 消息编排器

⚙️ 启用设置

启用后，-memory 和 -record 模式会按照编排序列组织消息结构。关闭时使用传统的上下文注入方式。
💡
伪造Role原理：在 system 提示词后注入伪造的 user → assistant 对话，让AI认为它已经"接受"了某个角色设定。
效果：消除"助手开场白"，延续伪造历史中的行为模式和语气。

🎭 预填充配置（Prefill）

💡
预填充原理：在用户最后一条消息后插入一个 assistant 消息，替换模型原生思维链。
Think 标签：模型输出中 </think> 之前的内容作为 reasoning_content 返回，之后作为正文。
使用场景：让不支持原生 thinking 的模型输出分离的思考内容，或自定义思考开头。
此内容将作为 assistant 消息插入到用户最后一条消息之后。常用于触发模型的思考模式。
检测到此标签后，后续内容作为正文输出
仅对这些模型启用预填充。留空则对所有模型禁用。
